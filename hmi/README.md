# HMI

GTX-A 차량 하부 점검 로봇의 **관제 화면**이다. 조작자는 이 화면 하나로 로봇을
보내고, 점검 지점을 돌리고, 사진을 찍어 남긴다.

로봇과는 raw TCP 로만 통신한다. 규약은 [bridge_protocol.md](../docs/bridge_protocol.md)
에 있다. 관제 PC 에는 ROS 2 를 설치하지 않는다 — 납품 대상이 산업용 Windows PC 이고,
거기에 ROS 를 얹으면 그 설치 상태가 곧 관제의 가동 조건이 된다.

## 실행

```bash
./build/inspection_hmi                  # 로봇에 접속 (기본)
./build/inspection_hmi --host 10.0.0.5  # 다른 주소로
./build/inspection_hmi --sim            # 내장 모형 — 로봇도 브릿지도 없을 때
```

### 어디에 붙는가

인자 없이 실행하면 **설정에 적힌 주소의 로봇 브릿지**에 붙는다. 실기든 MuJoCo
시뮬레이터(`robot:=sim`)든 같은 채널을 내므로 관제는 둘을 구별하지 않는다.

`--sim` 은 다른 뜻이다. ROS 도 브릿지도 없이 **관제 안에서 도는 모형**에 붙는다.
화면 배치를 보거나 로봇 없이 화면을 띄워야 할 때 쓴다. 이것으로는 연동이 되는지
알 수 없으므로, 연동 확인에는 쓰지 않는다.

기본이 실기인 이유가 이것이다. 기본이 모형이면 화면이 도는 것만 보고 "연동이
된다" 고 오해하기 쉽고, 정작 브릿지가 끊긴 것은 눈치채지 못한다.

### 인자

| 인자 | 뜻 |
|---|---|
| `--host <주소>` | 브릿지 주소. 설정값을 이번 실행에만 덮어쓴다 |
| `--port <번호>` | 브릿지 포트 (기본 9090) |
| `--sim` | 내장 모형에 붙는다. 옛 이름 `--testbed` 도 받는다 |
| `--view <이름>` | 시작 화면. `drive` `locations` `arm` `capture` `diagnostics` `data` `events` |
| `--dark` | 어두운 테마로 시작 |

개발용으로만 쓰는 것들: `--samples <폴더>` 표본 촬영 폴더, `--size 1280x760`
창 크기, `--manual` 수동 조작 패널, `--shot <파일>` 화면 캡처 후 종료,
`--shot-dialog <이름> <파일>` 대화상자 캡처.

`--shot` 은 로그인을 통과한 뒤에야 창이 만들어지므로 자동 실행에는 쓸 수 없다.
`--shot-dialog` 는 로그인보다 먼저 돌아 그대로 동작한다.

## 운용에서 알아둘 것

**로그인** — 실행하면 먼저 로그인 창이 뜬다. 지금은 자리표시 자격증명이다.

```
아이디    admin
비밀번호  admin
```

여기서 입력한 이름이 이후 **모든 조작 이력에 `by` 로 남는다**. 이 화면의
목적이 그것이다 — 코드에 박힌 비밀번호로 막을 수 있는 것은 없고, "누가
비상정지를 해제했나" 에 사후에 답할 수 있게 하는 것이 값이다.

끌 수 있는 길은 두지 않았다. 빌드 옵션으로 두었더니 개발 빌드와 납품 빌드가
서로 다른 경로로 떠서, 어느 쪽을 시험한 것인지 흐려졌다. 현장 계정 정책이
정해지면 `src/auth/Session.cpp` 한 곳만 고치면 된다.

**어느 로봇인지** — 상단 바 맨 왼쪽에 지금 조작 중인 로봇 이름이 뜬다. 로봇이
말해 주기 전까지는 비어 있다. 다른 로봇의 식별자가 같은 연결에서 오면 관제가
연결을 끊는다 — 주소를 잘못 적어 옆 로봇에 붙는 것을 막기 위한 것이다.

**실시간 영상은 없다** — 점검 사진은 정지 상태에서 찍어 로봇이 직접 NAS 로
보낸다(과업지시서 2.2.4). 관제로는 촬영 결과의 미리보기만 온다.

**설정 파일** — `~/.config/WEGO Robotics/Inspection HMI.ini`. 브릿지 주소,
테마, 배터리 복귀 기준, NAS 경로가 여기 있다.

## 빌드·테스트

```bash
cmake --preset dev
cmake --build --preset dev
ctest --preset dev
```

`release` 프리셋은 내장 모형을 넣지 않는다 — 납품 빌드에서 `--sim` 은 오류를
내고 종료한다. 로봇이 없으면 화면이 뜨지 않는 편이, 가짜
데이터로 도는 화면을 현장에서 진짜로 오해하는 것보다 낫다.

## 구성

| 경로 | 내용 |
|---|---|
| `src/` | 화면과 통신 |
| `src/RobotDef.h` | B2·FR3 의 관절 한계와 링크 치수. 이 표는 여기 한 곳에만 둔다 |
| `src/widgets/Robot3DView.h` | 3D 자세 뷰. OpenGL 을 쓰지 않는 이유가 파일 머리에 적혀 있다 |
| `testbed/` | `--sim` 이 쓰는 내장 모형 |
| `tools/make_robot_mesh.py` | 제조사 메시를 `resources/robot_mesh.bin` 으로 굽는다 |
| `tests/` | 단위 테스트 |
