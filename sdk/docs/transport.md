# 전송 계층

## 연결

| | 값 |
|---|---|
| 프로토콜 | TCP |
| 제어 포트 | `9090` |
| 상태 확인 | 같은 TCP `9090`의 `INSPECTION-PRESENCE/1` probe (HMI 목록 확인 전용) |
| 소켓 옵션 | `TCP_NODELAY` 필수 |
| 동시 접속 | **1** — 두 번째 연결은 즉시 닫힌다 |
| 바이트 순서 | 리틀 엔디언 |

`TCP_NODELAY` 를 끄면 Nagle 알고리즘이 작은 프레임을 모아 보내면서 조작 명령에
수십 ms 가 붙는다. 수동 주행에서 체감되는 수준이다.

동시 접속이 1인 것은 의도된 제약이다. 두 클라이언트가 같은 로봇에 명령을 보내면
어느 쪽이 무엇을 시켰는지 사후에 가릴 수 없다. 연결이 안 되면 먼저 붙어 있는
클라이언트가 살아 있는지부터 확인한다.

```bash
ss -tn | grep 9090
```

### UDP 를 쓰지 않는 이유

상태 스트림은 UDP 가 자연스러워 보이지만 쓰지 않는다.

**포트를 최소로 유지하기 위해서다.** 상태 확인도 제어 TCP `9090` 하나에서
끝낸다. HMI가 고정 probe를 보내면 브릿지는 고정 문자열만 반환하고 즉시 닫는다.

**손실 허용이 필요한 채널이 이미 처리된다.** 상태 채널은 `pub` 로 보내고
브릿지가 송신 큐가 밀릴 때 오래된 표본을 버린다. 애플리케이션 계층에서 같은
효과를 얻으므로 전송 계층을 나눌 이유가 없다.

**지도와 미리보기는 손실되면 안 된다.** PNG 수 MB 를 UDP 로 보내면 재조립을
직접 구현해야 한다. TCP 가 이미 하는 일이다.

## 프레임

```
 0        4                 8                   12
 +--------+-----------------+-------------------+---------------+---------+
 | magic  | body_len uint32 | header_len uint32 | header (JSON) | payload |
 +--------+-----------------+-------------------+---------------+---------+
          |<--------------------- body_len bytes ------------------------>|
```

| 필드 | 크기 | 값 |
|---|---|---|
| `magic` | 4 | `"SHLM"` = `0x4D4C4853` (리틀 엔디언 uint32) |
| `body_len` | 4 | `header_len` 필드부터 payload 끝까지의 바이트 수 |
| `header_len` | 4 | header JSON 의 바이트 수 |
| `header` | 가변 | UTF-8 JSON 봉투 |
| `payload` | 가변 | 이진 본문. 없으면 0 바이트 |

- 최대 `body_len` 은 **32 MiB**. 넘으면 연결을 끊는다.
- `header_len` 이 `body_len` 을 벗어나면 프레임이 자기모순이므로 연결을 끊는다.
- `magic` 이 틀리면 **재동기화를 시도하지 말고** 끊는다. 스트림이 어긋난
  상태에서 다음 `SHLM` 을 찾아 붙이면 남의 데이터를 프레임으로 읽게 된다.

구현은 각 플랫폼의 `cpp/include/inspection/framing.hpp` 에 들어 있다. 헤더
전용이고 의존성이 없다. 로봇과 관제도 같은 구현을 쓰므로 양쪽이 바이트 배치를
두고 어긋날 일이 없다.

### 부분 수신 처리

한 번의 `recv()` 가 프레임 여러 개를 줄 수도, 8바이트 머리말조차 다 주지 않을
수도 있다. 반드시 루프로 뽑아낸다.

```cpp
decoder.append(bytesJustRead);
inspection::Frame f;
for (;;) {
    const auto st = decoder.next(f);
    if (st == inspection::DecodeStatus::NeedMore) break;
    if (st != inspection::DecodeStatus::Ok) { close(); break; }
    handle(f);
}
```

한 번에 하나만 처리하면 오류 없이 지연만 쌓인다.

재연결할 때는 `decoder.reset()` 을 부른다. 이전 연결의 잔여 바이트가 남아
있으면 새 연결의 첫 프레임이 어긋난다.

## 봉투

```json
{"v":1,"t":"pub","ch":"state/pose","ts":1789123456.789,"seq":4210,
 "robot":"R1","p":{"x":1.2,"y":0.4,"theta":0.1}}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `v` | int | 예 | 규격 버전. 현재 `1` |
| `t` | string | 예 | 메시지 종류 (아래) |
| `ch` | string | `hb` 외 | 채널 이름 |
| `ts` | number | 예 | 송신자 시계, Unix epoch 초 (소수 포함) |
| `p` | object | 예 | 페이로드 |
| `id` | string | `req`/`res` | 요청·응답 상관 ID |
| `robot` | string | 아니오 | 로봇 식별자 (아래) |
| `seq` | int | 아니오 | 스트림 순번. 유실 감지용 |

### 메시지 종류 `t`

| 값 | 방향 | 뜻 |
|---|---|---|
| `hb` | 양방향 | 하트비트 |
| `sub` | 클라이언트 → 로봇 | 채널 구독 |
| `unsub` | 클라이언트 → 로봇 | 구독 해제 |
| `pub` | 주로 로봇 → 클라이언트 | 스트림 표본. 유실 허용 |
| `req` | 클라이언트 → 로봇 | 명령 요청 |
| `res` | 로봇 → 클라이언트 | 명령 응답 |
| `evt` | 로봇 → 클라이언트 | 비동기 이벤트. 구독과 무관하게 전달 |

수동 조작은 고객 SDK의 TCP API에 포함하지 않는다. HMI만 승인된 UDP teleop
경로에서 20 Hz deadman 패킷을 보낸다. E-Stop은 예외 없이 TCP 요청이다.

> **구현 현황** — 현재 브릿지는 `sub` 를 수신 기록만 하고 구독 목록으로 쓰지
> 않는다. 모든 상태 채널을 연결된 클라이언트에 발행한다. `sub` 는 보내도
> 무해하며, 나중에 실제 필터링이 붙어도 호환된다.

### `robot` — 누구에게, 누구로부터

로봇은 **나가는 모든 프레임에** 자기 식별자를 찍는다. 기본값은 `R1` 이며
launch 인자 `robot_id` 로 바꾼다.

클라이언트는 처음 들은 값을 고정하고, 같은 연결에서 다른 값이 오면 연결을
끊어야 한다. 클라이언트가 보내는 프레임에서는 비워도 된다 — 빈 값은 "이 연결에
있는 로봇" 이라는 뜻이다. 값이 있는데 로봇의 것과 다르면 로봇이 그 명령을
**실행하지 않고** `E_ROBOT_MISMATCH` 로 거절하며, 거절 응답에 자기 식별자를
실어 보낸다.

이 확인이 필요한 이유는 화면이 거짓말을 하지 않기 위해서다. 주소를 잘못 적어
옆 로봇에 붙어도 나머지는 정상으로 보이고, 그 상태로 비상정지를 누르면 아무도
보고 있지 않은 로봇이 선다.

사람이 읽을 이름은 `state/system` 의 `robot_name` 에만 실린다. 모든 프레임에
얹으면 초당 수십 번 같은 문자열을 나르게 된다.

## 하트비트

```json
{"v":1,"t":"hb","ts":1789123456.789,"p":{"seq":1024}}
```

- 양방향 **5 Hz**.
- 로봇은 받은 `seq` 를 그대로 되돌려 보낸다. 클라이언트는 이것으로 왕복 지연을
  잰다.
- 클라이언트 하트비트가 **1초** 이상 없으면 브릿지가 생존 신호 발행을 멈춘다.
- 실제 정지는 로봇의 안전 노드가 **1초** 통신 두절 계약으로 판단한다. 브릿지가 아니다.

브릿지는 링크가 이상하다는 사실을 알리고, 최종 정지 판정과 래치는 안전 노드가
담당한다.

## 연결 수명

```
연결 → (클라이언트) hb 시작 → 로봇이 상태 발행 시작
                                ↓
                    로봇이 현재 상태를 한 번 밀어 준다
                    (waypoints, locations, markers, map, mission)
```

새로 붙은 클라이언트가 빈 화면을 보지 않도록, 브릿지는 연결 직후 보관 중인
목록과 지도를 재발행한다. 저장된 지도를 쓰면 `map_server` 가 한 번만 발행하기
때문에 이 재발행이 없으면 나중에 붙은 클라이언트는 지도를 영영 못 본다.

**재연결해도 자율주행은 자동 재개하지 않는다.** 사람이 다시 시작해야 한다.

## 버전 불일치

봉투의 `v` 가 다르면 `E_VERSION` 을 응답하고 연결을 끊는다. 기능을 낮춰
이어 붙이지 않는다. 서로 다른 규격의 양쪽이 각자 정상이라고 믿으며 도는 것이
가장 위험한 고장 형태다.
