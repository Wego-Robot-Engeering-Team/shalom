# 오류

## 응답 형식

실패한 `res` 의 페이로드다.

```json
{"ok": false, "err": "E_MODE", "msg": "수동 모드에서는 자율 이동을 실행하지 않습니다"}
```

| 필드 | 설명 |
|---|---|
| `ok` | 항상 `false` |
| `err` | 오류 코드 (아래) |
| `msg` | 사람이 읽을 사유. 형식이 고정돼 있지 않으므로 **파싱하지 말 것** |

성공하면 `{"ok": true}` 이며 `err` 이 없다. 일부 명령은 `msg` 에 결과를 싣는다 —
`cmd/capture/trigger` 는 저장된 파일명을 돌려준다.

## 코드

| 코드 | 심각도 | 뜻 |
|---|---|---|
| `E_VERSION` | critical | 규격 버전 불일치. 연결이 끊긴다 |
| `E_ROBOT_MISMATCH` | critical | 다른 로봇이 응답했다. 연결을 끊어야 한다 |
| `E_HARDWARE` | critical | 하드웨어 응답 없음 |
| `E_BAD_PAYLOAD` | error | 필수 값 누락 또는 형식 오류 |
| `E_UNREACHABLE` | error | 경로·자세 계획 실패 |
| `E_LIMIT` | error | 관절·속도·작업공간 한계 초과 |
| `E_UNKNOWN_CHANNEL` | warn | 로봇이 모르는 채널 |
| `E_ESTOP_ENGAGED` | warn | E-Stop 발동 중 |
| `E_MODE` | warn | 현재 모드·상태에서 불가 |
| `E_BUSY` | info | 선행 동작 진행 중 |

위 열 개는 명령 응답의 `err` 필드에 실리는 것이 전부다. 프로그램이 분기하는
값이라 의도적으로 굵게 유지한다.

## 이벤트 코드

`evt/log` 로 오는 코드는 136 개이며 접두사로 출처가 구분된다.

| 접두사 | 번호대 | 영역 |
|---|---|---|
| `E_` | 1000 | 명령 거절 사유 |
| `LINK_` | 1100 | 전송 |
| `SYS_` `TF_` `MAP_` `UPDATE_` | 1200~1500 | 시스템·좌표계·지도·배포 |
| `SAFETY_` `MOTION_` | 2000 | 안전·모션 권한 |
| `NAV_` `MISSION_` `SETUP_` | 3000 | 자율주행·점검·사전 교시 |
| `PERCEPT_` | 4000 | 인식 |
| `ARM_` `BASE_` | 5000 | 로봇팔·본체 |
| `CAPTURE_` | 6000 | 촬영 |
| `POWER_` | 7000 | 전원 |
| `AUDIT_` | 8000 | 조작 이력 |

전체 목록은 [`hmi/resources/error_codes.json`](../../hmi/resources/error_codes.json)
에 있다. 원인과 조치까지 포함한 단일 출처이며, 이 파일과 코드가 어긋나면
테스트가 잡는다.

각 항목이 갖는 필드다.

| 필드 | 뜻 |
|---|---|
| `id` | 숫자 번호. 현장에서 부르고 매뉴얼과 대조한다 |
| `origin` | 발생처. `B2` · `FR3` · `D455` · `브릿지` · `안전 노드` 등 |
| `clears` | `latched`(사람이 해제) / `clears_with`(짝 코드) / `momentary` |
| `auto_action` | 시스템이 이미 한 일. `stopped` · `paused` · `returning` 등 |
| `throttle_s` | 반복 억제 간격. 없으면 억제하지 않는다 |
| `params` | 발생처가 인자로 정해지는 코드의 인자 이름 |

**`auto_action` 을 먼저 읽는다.** 조작자가 가장 먼저 알아야 할 것은 "시스템이
이미 무엇을 했는가" 이고, `actions` 는 "이제 무엇을 해야 하는가" 다.

## 처리 방침

**`critical` 은 연결을 끊는다.** `E_VERSION` 과 `E_ROBOT_MISMATCH` 는 계속
이어 붙이면 안 되는 상황이다. 규격이 다른 채로 도는 것, 그리고 다른 로봇을
조작하는 것은 둘 다 화면이 정상으로 보이면서 잘못된 기계가 움직이는 형태의
고장이다.

**`E_BUSY` 는 오류가 아니다.** 선행 동작이 끝나면 다시 보내면 된다. 조작자에게
경고로 띄우면 정상 동작을 고장으로 읽게 된다.

**`E_UNKNOWN_CHANNEL` 은 버전 차이의 신호다.** 로봇이 모르는 채널을 조용히
무시하지 않고 사유를 돌려주는 것은, 새 기능을 쓰려는데 아무 반응이 없으면
원인을 짚을 수 없기 때문이다.

**`msg` 를 파싱하지 말 것.** 사람에게 보여 주는 문장이며 예고 없이 바뀐다.
분기는 `err` 코드로 한다.

## 프로토콜 수준 실패

응답이 아니라 연결 자체가 끊기는 경우다.

| 상황 | 동작 |
|---|---|
| magic 불일치 | 즉시 종료. **재동기화를 시도하지 말 것** |
| `body_len` 이 32 MiB 초과 | 즉시 종료 |
| `header_len` 이 `body_len` 을 벗어남 | 즉시 종료 |
| 봉투 `v` 불일치 | `E_VERSION` 응답 후 종료 |
| 두 번째 클라이언트 연결 | 새 연결을 즉시 닫는다 |

프레임이 깨진 뒤에는 `evt/log` 로 `LINK_FRAME_CORRUPT` 이 발행되지만, 이미 끊긴
뒤라 **다음 연결에서야 전달된다.** 재연결한 클라이언트가 직전에 무슨 일이
있었는지 알 수 있게 하려는 것이다.

## 연결이 안 될 때

브릿지는 클라이언트를 한 대만 받는다. 앞서 띄운 클라이언트가 살아 있으면 새
연결은 즉시 닫힌다.

```bash
ss -tn | grep 9090
```

붙었는데 아무것도 오지 않으면 대부분 이 경우다.
